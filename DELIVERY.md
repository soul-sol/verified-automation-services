# Delivery and privacy rules

## Public request boundary

GitHub Issues are public. A request may contain:

- a public repository URL;
- a redacted error message;
- a high-level description of a workbook or workflow;
- desired output and acceptance criteria;
- an approximate deadline.

Do not post:

- credentials, tokens, API keys, cookies, or private URLs;
- personal, customer, employee, health, or payment data;
- private source code or proprietary workbook contents;
- passwords, access invitations, or production logs containing secrets.

If private material is required, the engagement does not proceed until an
appropriate private transfer method and deletion plan are agreed.

## Scope and payment

The listed prices are starting prices for the listed scope. Before payment, the
seller provides:

- exact inputs and outputs;
- exclusions and external dependencies;
- delivery date;
- acceptance tests;
- revision boundary;
- supported payment and delivery method.

GitHub does not process or escrow payment for these services. A request issue is
not an order, invoice, payment, or guarantee of availability.

## Delivery evidence

Every completed technical engagement includes the closest applicable evidence:

- test or reproduction command;
- before/after behavior;
- changed-file summary;
- limitations and remaining external blockers;
- rollback or source-preservation instructions where relevant.
